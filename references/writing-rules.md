# 受控中文寫作規則全集

本檔案是 `SKILL.md` 的參考層：規則展開、中文特有的坑、與上游 ASD-STE100 的對應關係、linter 規則名表、引用。
它**不復述** ASD-STE100 的正文，也不提供任何「受控詞表」—— 中文沒有這樣的官方標準，本技能給的是規則與方向。

## 一、上游是什麼

ASD-STE100 是受控自然語言，1986 年由現在的 ASD（歐洲航空航天與國防工業協會）發佈，起因是歐洲航空公司
需要「不會被讀錯的」英文維修手冊 —— 讀錯一條指令會死人。標準由 STEMG 維護，Issue 6（2013）起可免費取得，
當前版本 Issue 9（2025 年 1 月）。結構是：**9 節 53 條寫作規則** + 約 900 個受控詞（每個詞只有一個意思、
一種詞性）與約 1200 個需替換的詞 + 允許組織自訂術語表。

## 二、上游規則類別 → 中文對應

| 上游類別 | 上游要求 | 中文對應做法 |
|---|---|---|
| 詞義 | 一詞一義，只用受控詞義 | 一詞一義靠**全篇一致**：同一概念只用一個詞，不靠上下文區分 |
| 詞形 | 一個詞只有一種詞性 | 優先名詞或動詞中更直白的那個；不在同一段裡讓同一個詞換詞性 |
| 動詞 | 動作用動詞，不用動詞派生名詞（Rule 3.7） | 禁「進行 / 作出 / 加以 / 予以 / 給予 / 開展 + 動作名詞」；直接寫動詞 |
| 短語動詞 | 禁止動詞 + 介詞（Rule 9.3） | 中文對應：禁用「做一下處理」「搞一下最佳化」這類「動詞 + 一下 + 名詞」的含糊搭配 |
| 時態 | 只允許不定式、祈使、一般現在 / 過去 / 將來、過去分詞作形容詞；禁完成時 | 中文體貌從簡：「已經……了 / 正在……中 / ……過」只在**當前相關性**是資訊時保留，並在輸出裡標註 |
| 語態 | 程序與指令必須主動；被動只在施事未知或無關時（描述文） | 同。中文的被動檢查點是「被」字句與「由……所」結構 |
| 句長 | 程序 ≤ 20 詞，描述 ≤ 25 詞 | 漢字按「字」算：指令 ≤ 25 字，說明 ≤ 40 字（linter 預設 40，程序步驟用 `--max-chars 25`） |
| 一句一動作 | 一句話只給一個指令 | 同。中文最常見的違反形式是分號、「並且 / 同時 / 從而」串聯 |
| 不省略 | 主語、動詞、冠詞不能為省字而刪 | 中文對應：不省主語、不省量詞與範圍限定（「檔案未備份將遺失」→「未備份的檔案會遺失」） |
| 名詞簇 | 名詞堆疊 ≤ 3 個詞 | 中文對應：定語連綴 ≤ 3 層（「高壓燃油泵進口閥門總成」拆開） |
| 標點 | 分號一律不許（Rule 8.1），其餘標準標點可用 | 同：不用分號連接動作；破折號連接通常說明這句該拆 |
| 段落 | 一段一主題，≤ 6 句；≥ 3 步或 ≥ 3 個條件用清單 | 同 |
| 安全 | 安全指令以明確的命令或條件開頭 | 同。中文對應：不要用「建議注意」「請留意」這類軟表述替代命令 |

## 三、中文特有的坑（上游沒有，本技能新加）

上游是從英語的失敗模式裡長出來的。中文技術文字的失敗模式有相當一部分不重合，下面六條是本技能的增量：

1. **虛動詞**（進行 / 加以 / 作出 / 予以 / 開展 + 動作名詞）。中文獨有，英文對應物是 nominalization。
   它同時做三件壞事：句子變長、施事被藏起來、動作被抽象成名詞。
2. **套話**（需要注意的是、值得一提的是、在一定程度上、某種意義上、綜上所述、不難看出）。
   刪掉之後資訊量不變，屬於純雜訊。
3. **行銷形容詞**（無縫、強大、賦能、閉環、極致、絲滑、一站式、顛覆、領先）。
   標準做法是換成可測量的說法，或者刪掉這一句。
4. **同義輪換**。中文同義詞特別多（檢查 / 驗證 / 核對 / 核查），模型為了「語言豐富」會輪著用；
   讀者無法判斷它們是同一個動作還是四個動作。
5. **含糊限定**（若干、一些、相關、有關、適當、酌情、必要時）。中文技術寫作裡這類詞極易被當成
   「萬能修飾」；要麼給數量與範圍，要麼刪。
6. **翻譯腔**（基於……的情況下、對於……而言、這是一個……的事實、不僅……而且……而且）。
   多半是英文長句直譯留下的結構，刪掉外殼後主語和動作反而清楚了。

## 四、情態是內容

所有規則裡最容易出錯的是這一條：**「可能 / 也許 / 大概 / 有時 / 傾向於」承載作者的置信度，置信度是內容。**
把「請求可能已失敗」改成「請求失敗」不是簡化，是換了結論；把「可能是 X 導致的」改成「X 是原因」同理。
linter 因此**永不標記情態**，`--selftest` 裡有一條斷言：「請求可能已失敗。」必須乾淨。

例外是複合體貌：當「已經……了」表達的是**當前相關性**（「任務已完成，結果可以直接讀」）而不是歷史時，
保留它並標註這處偏離；純粹的歷史陳述可以簡化。

## 五、linter 規則名表

| 規則名 | 嚴重度 | 查什麼 |
|---|---|---|
| `semicolon` | 硬 | 分號把兩件事串進一句 |
| `long-sentence` | 硬 | 句長超過 `--max-chars`（預設 40 字） |
| `nominalization` | 硬 | 虛動詞 + 動作名詞 |
| `marketing-adjective` | 硬 | 行銷形容詞表命中 |
| `empty-phrase` | 硬 | 套話表命中 |
| `synonym-rotation` | 硬 | 同義組內兩個以上成員在同一檔案出現 |
| `passive-voice` | 建議 | 「被」字句 |
| `compound-aspect` | 建議 | 已經……了 / 正在……中 |
| `vague-word` | 建議 | 若干、一些、相關、適當、必要時…… |
| `halfwidth-punct` | 建議 | 中文句中的半形標點 |
| `dash-join` | 建議 | 破折號連接 |

硬違規總數超過 `--baseline`（預設 0）時退出碼 1；建議類只報告。`--json` 出結構化結果，
`--list-rules` 列出全部，`--disable 名,名` 關掉指定規則。

口徑說明：linter 只做**機械首查**。它不比較原文與改寫、不判斷情態強度有沒有變、不證明原意被保留。
零違規只說明這幾項機械檢查沒有發現問題。
